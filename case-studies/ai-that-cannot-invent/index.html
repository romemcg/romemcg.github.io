Designing AI that cannot invent facts

CareerOS, personal project, 2026.

  1. 1Master CV
    →
  2. 2Verified fact store
    →
  3. 3AI selects and orders
    →
  4. 4Tailored CV

The problem

AI writing tools will invent metrics if asked, and screeners probe for consistency. In a job search, one fabricated number can end an application.

What I did

  • Split the system in two: a verified fact store, and an AI step that only selects and orders from it.
  • Made the rule structural, not a prompt instruction, by enforcing it in the database.
  • Kept everything on the local machine, with the API key in the keychain.

Decisions and trade offs

  • Constrain the system instead of trusting the model.
  • Verification is a human step, done once, then reused.
  • Local first, because the data is private.

Outcome

  • The fact importer and verification screen work on a real master CV.

What I took from it

Reliability in AI products usually comes from the structure around the model.
